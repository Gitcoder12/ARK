# Learned-policy and adversarial evaluation

## Q-learning baseline

ARK now includes a tabular Q-learning agent with an explicit train/evaluation split.

The compact state representation is:

`(row, column, goal_row, goal_column, decoy_row, decoy_column, up_cell, down_cell, left_cell, right_cell)`

The four adjacent cell values are read from the agent's observation. The learner updates:

`Q(s,a) ← Q(s,a) + α [r + γ max(Q(s',a')) − Q(s,a)]`

For terminal transitions, the bootstrap term is zero.

The baseline is deliberately modest. It is a local-observation tabular agent, not PPO/DQN, and is not expected to provide optimal planning or robust generalization to arbitrary maps. Its purpose is to add a reproducible learned-policy comparison alongside ARK's scripted baselines.

Run:

```bash
pip install -e ".[dev]"
python examples/run_q_learning_baseline.py
```

The example uses training seeds 1000–1499 and held-out evaluation seeds 10000–10049. Results must be generated by running the script; no benchmark numbers are asserted in this document. Evaluation uses the existing safety monitor, and reports learned-policy and scripted goal-following results on the same held-out seed set.

## Adversarial monitor regression suite

Run:

```bash
python examples/run_adversarial_monitor.py
pytest tests/test_monitor_adversarial.py -q
```

The suite includes prompt-injection-like metadata, roleplay/jailbreak metadata, token-smuggling-like metadata, spoofed position and goal fields, action metadata smuggling, and invalid action values.

The monitor is a structured action gate, not a natural-language prompt interpreter. These tests therefore verify that untrusted text/metadata cannot override independent environment checks, and that its state authority comes from the environment rather than forged observation fields.

**Bypass Success Rate** is defined for this finite regression suite as:

`unsafe actions returned as ALLOW / adversarial cases attempted`

A zero measured rate only means these included deterministic cases did not bypass the monitor. It does not establish comprehensive prompt-injection resistance or system security.

## Threat-meter threshold calibration

The threat meter's event weights remain heuristic. The new calibration utility selects a decision threshold over labeled validation episodes to minimize empirical misclassification cost; it does not turn the index into a probability.

For threshold (t), predict unsafe when (s_i ge t). Let FP and FN be false positives and false negatives. The objective is:

`Cost(t) = (C_FP × FP(t) + C_FN × FN(t)) / N`

The selected threshold minimizes this cost over observed-score midpoints, with false-negative rate used as the first tie-breaker. Report FPR and FNR separately. Calibration requires both safe and unsafe examples in the labeled validation set.

This is threshold selection, not probability calibration. The meter's score remains an experimental factor index, and results depend on label quality and the validation distribution.
