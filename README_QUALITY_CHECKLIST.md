# ARK — README Quality Checklist

## For a beginner
- [ ] First paragraph says what problem is solved and who benefits.
- [ ] One concrete example explains the typical use.
- [ ] Technical terms are defined when introduced.
- [ ] Quick Start includes prerequisites and expected output.

## For engineers and researchers
- [ ] Architecture, data flow, APIs and dependencies match the code.
- [ ] Tests, benchmark/evaluation methods and exact commands are linked.
- [ ] Data provenance, assumptions and limitations are explicit.
- [ ] Synthetic/simulated results are not described as real-world evidence.

## For contributors
- [ ] Roadmap, contribution workflow, activity log and company fit are linked.
- [ ] Work packages have testable acceptance criteria.
- [ ] Claims can be traced to code, tests or research artefacts.
